# 星海工坊 2.0.0-dev.31

本版在 dev.30 的结构化人物变量基础上，把人物发布入口改成“宽进严出”的智能导入工作台。

## 人物发布默认流程

1. 粘贴整段人物设定，或直接导入 SillyTavern 世界书 JSON。
2. 点击“智能整理人物”。
3. 工坊复用 SillyTavern 当前已经连接的模型，通过 `SillyTavern.getContext().generateRaw()` 做隐藏的原始生成；不会向正常聊天框发送消息，也不会推进剧情。
4. 优先使用 JSON Schema 结构化输出；如果当前 API / 模型不支持结构化输出，则退回“只返回 JSON”的 raw generation，再由客户端本地 Normalizer 校验和清洗。
5. AI 只负责语义拆分：基础资料、长期事实、特性、招式、物品、真正星器、钩子 / 秘密、待分类信息。
6. 招式的本地档位与蓝耗不由 AI 自由编数字，而由客户端固定适配表根据语义强度映射。
7. 生成只读预览；普通玩家可以直接发布。高级变量编辑保留，但不再要求补齐名称、系别、类型、档位、蓝耗等“作业”。
8. 原始作者文本永久保存在人物 `source.rawText`，结构化失败或以后重新整理时仍有原始依据。

## dev.30 结构继续沿用

- `人设.长期事实.<短标题>`
- `特性.<名称>.{系别,类型,效果}`
- `招式.<名称>.{档位,系别,类型,蓝耗,效果}`
- `背包.<名称>.{数量,类别,描述}`
- `星器.<名称>.{类型,品阶,契合,效果}`
- `关系.钩子` / `关系.秘密`
- 主角和重要人物都支持 `特性`；魔法少女 / 守护者和魔人主角共用 `/主角/特性`。

## 世界书导入

人物页有独立的“导入世界书并整理”按钮。客户端先读取 `entries`，如果提前填写人物名，会优先筛选提到该人物的条目及邻近条目；然后才把文本交给当前模型做语义整理。单文件限制 4 MiB，送入模型的聚合文本最多约 120k 字符，并按约 30k 字符分块处理。

## 本地能力适配

AI 只返回 `powerTier` 语义级别，客户端固定映射：

- basic → 基础攻防 / 4 蓝
- minor → 小技能 / 35 蓝
- medium → 中技能 / 145 蓝
- major → 大技能 / 440 蓝
- domain → 领域 / 1250 蓝
- rule → 规则级 / 3500 蓝
- unknown → 小技能 / 35 蓝

这些数值均落在 dev.30 已有的档位合法区间内。高级编辑允许用户覆写；非法或空机械值会回到本地安全适配。

## 云端与冻结模块

`person` 仍使用 XYWS Package v1 的 `payload.source[] + fallbackText`。当前 publish / read / manage 后端对 `person.payload.source[]` 不做深层字段裁剪，因此 dev.31 不需要数据库迁移，也不需要重新部署三个云函数。

Discord OAuth、CloudBase Session、公共读取、云端发布、ownership / manage、数据库 `content_type`、compat 等已闭环模块不重构。
