# 星海工坊 2.0.0-dev.25

本版在 dev.24 结构闭环上重构人物/生灵发布器，并与开场白 V1.3、NPC 控制台 V2 统一人物分类契约：技能、星器、背包、躯体、状态、关系与叙事设定分开保存，不再把未知内容集中塞进钩子/秘密。另细化玩法、装束、能力、物品、规则等发布表单。OAuth/Auth/compat、云端后端与数据库结构保持冻结。

# 星海工坊 · SillyTavern 第三方扩展

当前客户端：`2.0.0-dev.25`。

星海工坊用于发现、发布、下载并安装社区作品。现有 Discord 登录、CloudBase Session、ownership、公共作品读取、云端发布、删除权限与跨客户端刷新继续沿用已实机成功的链路；dev.25 继承 dev.24 与 `xywsworksmanage stage3.7a-r1` 的作者编辑、真实点赞和下载计数闭环；本次只扩展客户端人物结构与发布表单，认证链和现有云端协议保持冻结。

## 安装

在 SillyTavern 的「扩展 → 安装扩展」中填写：

```text
https://github.com/suyunsu797/starsea-workshop.git
```

安装完成后刷新 SillyTavern。

## dev.25 重点

- 人物 / 生灵发布页按现有 `/重要人物/<姓名>` 合法结构重做：档案、战力、状态、侵蚀、星灵、躯体、招式、星器、背包、关系逐栏填写。
- 新增独立 `source.notes` 叙事设定：性格、口癖、背景、动机、习惯、弱点、战斗风格、本源、待分类补充。它们不伪造进 MVU，也不再挤进 `关系.钩子/秘密`。安装到本局时合法 MVU 先直接写入；叙事设定另外写入聊天框供用户检查发送。
- 从开场白命名档案发布人物时，`state.role` 明确优先：当前选魔法少女就只转换魔法少女字段，当前选魔人就只转换魔人字段；不会因作品标题/标签误把另一侧旧草稿一起发布。开场白附加人物 roster 也不会并入主角作品。
- 世界书转人物 / 生灵时，原文保存在 `source.notes.freeform`，不再塞到钩子。
- 装束发布细化到部位、材质、附件、武装、光效和受损表现；能力增加发动/范围/持续/限制/副作用；物品增加来源/使用/限制/特殊效果；玩法模板补足核心循环、节奏、资源、事件、失败和 AI 边界。以上仍编译到既有 payload，不增加数据库 content_type。

## dev.24 重点

- 全部作品类型都有“简介（选填）”；作者留空时，客户端会按正文或结构化字段自动生成卡片简介。
- SillyTavern 世界书 JSON（顶层 `entries`）可直接识别；导入前先选择目标栏目，条目 `content` 原文逐字保留。dev.25 中导入到人物 / 生灵时原文单独保存在 `source.notes.freeform`，不会整段偷塞进钩子等结构化字段。
- 本地导入作品在“我的”里增加“上传云端”，上传前可重新选择栏目并修改名称、简介、正文或结构化字段。
- 当前账号自己的云端作品增加“编辑作品”入口；配套 stage3.7a-r1 后端后，PATCH 会原地更新同一个作品 ID，不需要删除重发。
- 点赞 / 下载计数走现有管理端点：点赞按登录账号幂等记录并由数据库触发器原子维护 likes；成功安装或导出会真实递增 uses。卡片、详情与热门排序读取的仍是 `xyws_works.likes / uses`。
- dev.22 的完整人物 / 生灵结构化发布、装束、能力、物品与分类栏改动继续保留。

## 变量原则

工坊安装器只写现有 canonical MVU 结构，不为分享功能私造第二套长期状态。世界书、星辉内核、Zod 与事件推进器不是本扩展的配置文件，不随普通工坊 UI 修改而改写。

## 登录说明

正式登录链仍是香港 SCF 的同标签页 Discord OAuth → CloudBase Custom Login Session。不要恢复旧的 popup / `window.opener` / `BroadcastChannel` 登录方案。

## 安全

公开仓库只包含客户端扩展。CloudBase / Discord Secret、私钥、数据库凭据和服务端 API Key 不应提交到仓库。
